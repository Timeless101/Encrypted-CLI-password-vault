🧾 Project Write-Up
🔐 Encrypted CLI Password Vault

📌 Overview
The Encrypted CLI Password Vault is a command-line application that securely stores and retrieves user credentials. It is protected by a master password and uses encryption to ensure that sensitive data is not stored in plain text.
This project focuses on security, error handling, and clean architecture, rather than UI.

🎯 Goals
This project is designed to:
Improve error handling and edge-case thinking
Enforce secure coding practices
Strengthen application architecture
Remove reliance on GUI and focus on logic
Simulate a real-world tool

⚙️ Core Features

🔑 Authentication
User sets a master password
Password is hashed, not stored in plain text
Required to unlock the vault

📦 Vault Operations
- Add Entry
- vault add
- Store:
- Service name
- Username/email
- Password (encrypted)
- Get Entry
- vault get <service>
- Decrypt and display stored credentials
- List Entries
- vault list
- Show all stored service names (no passwords)
- Delete Entry
- vault delete <service>
- Remove an entry from the vault

🔐 Security Design
- Password Hashing
- Master password is hashed using a secure algorithm (e.g. bcrypt)
- Prevents recovery of the original password
- Encryption
- Stored passwords are encrypted using a symmetric encryption method
- Data is unreadable without the master password
- Secure Randomness
- Use Python’s secrets module instead of random

🚫 Explicit Non-Goals
- No plain-text password storage
- No logging of sensitive data

🏗️ Architecture
The project should be split into clear modules:
cli.py Handles:
- Command parsing
- User input/output
- vault.py

Core logic:
- Add/get/delete/list entries
- Coordinates other modules

crypto.py Handles:
- Hashing master password
- Encrypting/decrypting vault data

storage.py Handles:
- Reading/writing to file or database
- Data persistence

🔁 Data Flow Example
Adding a password:

1. User runs vault add
2. CLI collects input
3. Vault validates input
4. Password is encrypted via crypto.py
5. Encrypted data is stored via storage.py

⚠️ Error Handling (Critical Requirement)
The system must handle:

- Incorrect master password
- Missing entries
- Duplicate services
- Corrupted or missing storage file
- Invalid user input

🧪 Example Edge Cases
- Trying to retrieve a non-existent service
- Vault file deleted manually
- Wrong password entered multiple times
- Empty input fields

📂 Storage Options

🧠 Key Learning Outcomes
By completing this project, you will:

- Develop a security-first mindset

🚀 Possible Extensions (After Completion)
Only after the core is solid:

- Clipboard copy support
- Password generator using secrets

🏁 Success Criteria
The project is considered complete when:

- All data is securely stored (no plain text)
- All core commands work reliably
- Errors are handled cleanly and predictably
- Code is modular and readable
